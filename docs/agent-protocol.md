# Agent protocol: the rules every agent follows in a multi-agent session

The standing rules for any agent (Claude, Codex or another) working on Reports that Matter while other agents work beside it. A supervisor hands this file to every agent it spawns; a session may add a dated note on top (`~/src/reportsthatmatter/.agent-protocol-<date>.md`), and where they differ the dated note wins for that session. Folded in from the 2026-10-02 and 2026-10-09 session protocols. The procedure that applies these rules to a fix is the `fix-agent` skill; the skills index is in [AGENTS.md](../AGENTS.md#skills).

**Layout.** `~/src/reportsthatmatter/` holds the site repo `reportsthatmatter/` (shared checkout on `main`: never switch branches, stash or reset there), `ingest/` (shared checkout of `@rtm/ingest` on `main`: same rule), and one sibling repo per report (e.g. `jack-smith-report/`, `uk-leveson-inquiry/`; `reports/manifest.yaml` maps report ids to them). The Beads database lives in `reportsthatmatter/` (`bd show <id>`, `bd update <id> --append-notes "..."`). Read [AGENTS.md](../AGENTS.md) (especially "Work streams", "Bead levels and handoff-ready beads" and "Working conventions"), [report-pipeline.md](report-pipeline.md) and [`scripts/ingest/README.md`](../scripts/ingest/README.md) before starting.

## Rules

1. **Worktrees, named `<kind>-<slug>-<MMDD>`.** Site: `git -C ~/src/reportsthatmatter/reportsthatmatter worktree add ~/src/reportsthatmatter/rtm-<slug>-<MMDD> -b <branch> origin/main`, then `pnpm bootstrap` in it (never symlink `node_modules`). Ingest: `git -C ~/src/reportsthatmatter/ingest worktree add ~/src/reportsthatmatter/ingest-<slug>-<MMDD> -b <branch> origin/main`, then `CI=true pnpm install`. Report repos: `pnpm ingest worktrees <id…>` from your site worktree, then export the `RTM_REPORT_DIRS` it prints. Use absolute paths with `git -C` (a relative path is relative to `-C`, not your shell). You own only the report repos you were told you own.
2. **Pipeline fixes go in ingest, as passes.** Prefer an opt-in pass the report declares in its `ingest.ts` over changing a shared default. If you change a shared default, measure every report's move and say so.
3. **Test against your unreleased ingest** with `pnpm ingest try <branch|path> [<id>…]` or `pnpm ingest link <ingest dir>` (undo: `pnpm ingest link --restore`); see `scripts/ingest/README.md`, "Changing the library". Never commit a link override.
4. **Do not release.** Do not merge, tag, deploy, publish, seed, or run anything against production D1 (`wrangler d1 execute --remote`, `seed-highlights --remote`). Push branches and open PRs; describe any pin bump needed. One integrator ships after a reviewer agent's review.
5. **Measure.** Before/after numbers for your defect across the report (and across the corpus for a shared pass). Run `pnpm ingest check`, `pnpm corpus check` and `pnpm quality check` and read the diffs. If a signal improves, run `pnpm quality ratchet` and commit the result in your PR. Never `accept` or `baseline` just to quieten a check. Look at the rendered pages for the bead's examples.
6. **Peer noise.** If `verify.sh` or `corpus check` fails only for reports you do not own, run `git -C ../<repo> status`: that is peer noise; note it and move on. Never `pkill -f scripts/verify.sh` (it kills other agents' runs).
7. **Editorial.** If your report's paragraph ids move, update `editorial/<id>.yaml` in your site PR (source only; never commit `src/generated/editorial.ts`).
8. **Beads.** Append notes to your bead(s) (`bd update <id> --append-notes "..."`). Do not close them (the integrator closes on ship), except in a verify-and-close batch (the `burn-down` skill). File new defects handoff-ready (the `bead-writing` skill) with `--deps discovered-from:<id>`, one `stream:*` label and one `level:*` label. For a defect class no check caught: add the example to the quality catalogue (`docs/design/2026-10-02-quality-harness-catalogue.md` §3) in your PR and file a `stream:quality` bead for the signal or golden page that would catch it (`reportsthatmatter-b78.1`, the old collecting bead, is closed). Run `bd dolt push` after your bead writes.
9. **Final report** (your last message): branches and PR URLs; the passes or options a report's `ingest.ts` must declare; before/after measurements; every report whose text or ids move; editorial changes; the pin bump needed; anything unfinished; any real question for Rufus, logged as a `needs-user` or `decision` bead, not just mentioned. Keep it tight.
10. **Markdown files: never hard-wrap.** One line per paragraph or list item. Commit messages and PR bodies: plain.
11. **Keep going without asking for input.** Make reasonable, reversible decisions and record them.
12. **Decisions.** Questions of direction get a record in `docs/decisions/` (copy `0000-template.md`) and a bead labelled `decision`; never settle them in chat.
13. **Retro** (required, the last section of your final report), headed "Getting better faster": what slowed you down; what check, tool or reference text would have caught your defects earlier or measured your fix directly; one concrete proposal.
14. **Lessons.** Append the lessons worth keeping (one line each, with the bead or doc as evidence, in the format at the top of the file) to `docs/design/lessons.md` in the same PR.
15. **Usage limits.** If you may be cut off, keep your branch in a state that says where you were: commit work in progress with a `WIP:` message and push. The supervisor resumes you.
