# Beads Work-Tracking Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `NEXT.md` with a live Beads queue for agent-actionable work while retaining GitHub for human/public backlog and discussion.

**Architecture:** Seed six Beads from the current active GitHub queue, using priorities and labels so `bd ready` becomes the sole next-work view. Remove the duplicate repository queue, update local workflow documentation, and repoint GitHub issue #77's onboarding text to Beads.

**Tech Stack:** Beads 1.1.2 with embedded Dolt, Git, GitHub CLI, Markdown.

## Global Constraints

- Every agent-actionable task is a Bead; Beads owns active status, priority, dependencies, acceptance criteria, and operational detail.
- `bd ready` plus Bead priority replaces static next-work lists and a `next` label.
- GitHub retains public discussion, human-created requests, report candidates, broad epics, and historical context.
- Create only the six specified seed Beads; do not bulk-import the GitHub backlog or close/rewrite GitHub issues.
- A Bead must carry the matching GitHub issue as its external reference when one exists.
- Preserve historical `NEXT.md` mentions in completed plans.
- The sole external write is the explicitly authorized update to GitHub issue #77.
- Do not deploy, publish report content, or add a public changelog entry for this internal workflow change.

- [ ] **Step 1: Confirm the migration starts from an empty Beads queue**

```bash

```

Expected: zero existing issues, so no task IDs or state can be overwritten.

- [ ] **Step 2: Create the OCR-review Bead at P0**

Run:

```bash
bd create "Review OCR suspect queues, starting with Challenger" \
  --type task --priority P0 --labels ingestion,editorial \
  --external-ref https://github.com/reportsthatmatter/reportsthatmatter/issues/122 \
  --description "Review the 999 open OCR suspects through each report's fidelity workflow. Start with challenger-accident, the largest and messiest queue; record either a deterministic correction or a dismissal so each reviewed suspect leaves the queue permanently." \
  --acceptance "Review Challenger suspects against the source PDF; record each outcome in the report-owned correction/dismissal data; run the report's prescribed ingestion and fidelity checks; inspect rendered output; leave an updated queue count."
```

- [ ] **Step 3: Create the five remaining active Beads**

Run each command:

```bash
bd create "Make per-chapter footnote identities safe for Leveson" \
  --type bug --priority P1 --labels ingestion,footnotes \
  --external-ref https://github.com/reportsthatmatter/reportsthatmatter/issues/121 \
  --description "Leveson restarts footnote numbering by chapter, while the ingestion pipeline treats a number as report-global. Correct identity and rendering without making marker-linking unsafe." \
  --acceptance "Every rendered Leveson footnote reference resolves to its own chapter-local definition; no output exceeds deployment asset limits; ingestion checks and rendered-page inspection confirm the result."

bd create "Recover structural headings for Hillsborough" \
  --type task --priority P2 --labels ingestion,headings \
  --external-ref https://github.com/reportsthatmatter/reportsthatmatter/issues/125 \
  --description "Hillsborough headings are expressed by colour and weight, not textual syntax, so pdftotext flattens them into body text and sections are poorly structured." \
  --acceptance "The report declares any needed report-specific extraction knowledge; section headings and contents become meaningful; all fidelity gates pass; rendered sections and full view are visually inspected."

bd create "Make remote D1 search-index application reliable" \
  --type bug --priority P2 --labels deploy,search \
  --external-ref https://github.com/reportsthatmatter/reportsthatmatter/issues/123 \
  --description "The documented wrangler D1 remote file import failed with Cloudflare authentication error 10000 although remote commands authenticated. Establish and document a reliable remote index-application path." \
  --acceptance "A fresh remote search-index SQL file applies successfully with documented credentials and command; production search is checked against the newly indexed content; the deployment instructions accurately describe the working command."

bd create "Establish a safe extraction path for FCIC digits" \
  --type task --priority P2 --labels ingestion,extraction \
  --external-ref https://github.com/reportsthatmatter/reportsthatmatter/issues/102 \
  --description "FCIC's text layer silently loses every digit. Find a trustworthy extraction path and add a corpus-level detector so this failure is visible before publication." \
  --acceptance "FCIC digits are preserved or the report remains explicitly unpublished; a digit-loss detector fails on a representative broken input; fidelity and rendered-output review demonstrate the chosen path is safe."

bd create "Address remaining footnote recall and heading-quality cases" \
  --type task --priority P3 --labels ingestion,footnotes \
  --external-ref https://github.com/reportsthatmatter/reportsthatmatter/issues/104 \
  --description "Work through the bounded ingestion-quality remainder: missing footnote links, PSI truncated headings, and heading ambiguity where it harms a report." \
  --acceptance "Each adopted fix belongs in the pipeline or report declaration, has a failing case before the fix, passes fidelity and corpus checks after re-ingestion, and has been checked on rendered pages."
```

### Task 2: Remove the duplicate queue and document the work-tracking policy

**Files:**
- Delete: `NEXT.md`
- Modify: `AGENTS.md:15-23` (the existing `## Beads` section)
- Modify: `docs/beads-sync.md`

**Interfaces:**
- Consumes: The six Beads created in Task 1.
- Produces: Local instructions that point agents to `bd ready`, never to a static `NEXT.md`.

- [ ] **Step 1: Replace the `AGENTS.md` Beads section with the durable policy**

Replace the existing Beads paragraph with prose that states all of the following:

```markdown
Beads is the source of truth for agent-actionable work. Start each session with
`git pull`, `bd dolt pull`, and `bd ready`; create or update a Bead for work an
agent can undertake, including work linked to a GitHub issue. Beads owns task
detail, status, priority, dependencies, and acceptance criteria. GitHub keeps
human-created/public issues, report candidates, broad epics, and discussion.
Do not maintain a separate next-work list. At session end run `bd dolt push`
before committing and pushing. See `docs/beads-sync.md` for commands and sync
recovery. JSONL export is for inspection and interchange, not sync or backup.
```

- [ ] **Step 2: Add task-queue guidance to `docs/beads-sync.md`**

After the start-session commands, add a `## Choose and record work` section:

```markdown
Run `bd ready` to find unblocked work; priority determines the order within
that queue. Do not keep a separate `NEXT.md` or `next` label. Create a Bead
before starting any agent-actionable task, use labels for domain grouping and
dependencies only for genuine blockers, and set `--external-ref` when the task
has a related GitHub issue. Keep public discussion, report candidates, and
broad epics on GitHub until there is a concrete task to perform.
```

Update the existing work examples to use the `reportsthatmatter-` ID prefix and show `bd ready` before `bd create`.
