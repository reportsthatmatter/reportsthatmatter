# The unattended run — how to start one, and what it may do

**Date:** 2026-08-21
**Status:** live configuration
**Builds on:** [`2026-08-01-loop-engineering-setup.md`](2026-08-01-loop-engineering-setup.md),
which argues for the harness. This is the harness as configured, and the queue
it works through.

---

## Starting one

```bash
export RTM_LOOP=1     # arms the Stop hook for this session
```

`.claude/settings.json` wires the `Stop` hook to `scripts/stop-hook.sh`, which
blocks the turn from ending while `scripts/verify.sh` fails. `RTM_LOOP` is the
opt-in because the full check boots a worker and a browser and takes the better
part of a minute — right once per loop iteration, miserable on every turn of an
interactive session. Without it the hook exits 0 immediately.

Then either:

```
/goal every agent-ready issue in the queue below is closed and scripts/verify.sh exits 0
```

or, for a paced sweep rather than one continuous build:

```
/loop 30m work the next item in docs/plans/2026-08-21-loop-run.md
```

## The queue

Ordered. Each is a GitHub issue with the design already settled; none has an
open question, which is the property that makes a loop productive rather than
inventive.

## What the run must not do

Carried from the guard rails in the setup doc, and unchanged:

- Don't rewrite or force-push `main`; work on a branch.
- Don't edit `docs/v2-features.yaml` to make a goal pass. An entry that cannot
  be met is marked blocked, with a reason.
- Don't modify tests to make them pass; fix the code.
- Don't weaken a fidelity check to make a report pass. Mark it
  `ingested: false` with the reason.
- No external posting, account creation, or scheduling. Campaign material is
  drafted in-repo only.
- Stop and report if `verify.sh` fails the same way three iterations running.

Two more, from what this design touches:

- **Don't deploy a change to reader-facing storage unattended.** #96 records
  something about readers; it can be built and verified locally, and shipping it
  is a decision with a person's name on it.
- **Don't publish a visual direction (#99) unattended.** Produce options,
  render them, and leave the choice.

## Why the queue is ordered the way it is

Cheapest-first would put #14 at the top. It is not there because the two items
above it are the ones that get *worse with delay*: every report ingested before
#12 carries the defect into published text, and every week the mechanism in #95
is not shipped is a week readers cannot keep what they find. Nothing else on the
list decays.
