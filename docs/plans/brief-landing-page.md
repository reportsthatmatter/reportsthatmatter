# Homepage build brief for Reports that Matter

NB: Please create this in new `site` directory. It should be implemented in HTML + Tailwind CSS (use tailwind cdn so no build is needed).

What is included with this brief:

1. **Homepage draft text**: see `docs/plans/draft-landing-page.md`.
2. The **Official Inquiries – the Idea deck** see assets/Official Inquiries – the Idea.pdf. This is a potential source for screenshots, example walkthroughs, and conceptual foundation.
3. A short positioning note: see `docs/PRODUCT.md`.

### 1. Purpose of this page

Build a long-scroll homepage that:

* Makes the problem immediately concrete and undeniable.
* Demonstrates, not just explains, why Reports that Matter must exist.
* Establishes credibility through evidence, not branding.
* Funnels interested users toward exploration, sharing, and light subscription.

This is not a marketing landing page in the conventional sense. It is a **public-interest explanation + proof-of-need page**.

### 2. Target user (primary)

* Journalists, researchers, civic actors, policy-adjacent readers.
* Educated, curious, time-constrained.
* Likely to arrive skeptical, leave persuaded if shown evidence.

Secondary:

* Broad educated public arriving via search or shared excerpts.

### 3. Core narrative (what the page must communicate)

In one sentence:

> Important public reports exist, but are effectively unusable online — Reports that Matter fixes that.

The page must move the reader through four states:

1. Recognition: “Yes, this is broken.”
2. Understanding: “This is a systemic problem, not a one-off.”
3. Clarity: “I see exactly what this project does.”
4. Trust: “This is serious, useful, and worth paying attention to.”

### 4. Content structure (required sections)

The homepage should be a **long scroll**, not a lean hero page.

#### Section 1: Problem statement (hero)

* Headline: problem-focused, plain language.
* Short paragraphs, no jargon.
* No calls to action yet.

#### Section 2: What Reports that Matter does

* Simple explanation of the solution.
* Bullet points are acceptable.
* Emphasise: discoverable, readable, linkable.

#### Section 3: Concrete examples (critical)

This is the most important section after the hero.

* Two detailed case studies:

  * US Senate Financial Crisis report.
  * Saville Inquiry (UK).
* Each example should include:

  * Brief context (why the report matters).
  * “What actually happens today” walkthrough.
  * Screenshots from the original deck.
* This section should feel evidentiary, not promotional.

#### Section 4: Systemic framing

* Make clear this is a repeatable failure pattern.
* Bridge from examples to general problem.

#### Section 5: What changes with Reports that Matter

* Show principles:

  * deep links,
  * full text,
  * permanence,
  * web-native access.
* Avoid implementation detail unless illustrative.

#### Section 6: Why this matters

* Public-interest framing.
* No moralising; factual and grounded.

#### Section 7: Scope and status

* UK + US focus.
* Independent, public-interest project.

#### Section 8: Light engagement

* Options such as:

  * “Explore reports”
  * “Get updates when new reports are surfaced”
* Keep CTAs understated.

---

### 5. Visual and UX guidance

#### Visual tone

* Serious, documentary, understated.
* Prioritise readability over brand flourish.
* Screenshots are assets, not decoration.

#### Layout principles

* Generous whitespace.
* Clear typographic hierarchy.
* Screenshots inline with explanatory text.
* Long-form reading should feel comfortable.

#### Interaction

* No aggressive pop-ups.
* Subtle prompts only after value is demonstrated.
* Links should feel trustworthy and stable.

### 7. Non-goals (important to state)

* This page is not optimised for conversion-first marketing.
* It is not a product feature overview.
* It is not a blog index.
* It should not feel like a startup pitch.

Clarity, evidence, and trust matter more than brevity.

---

### 8. Success criteria for the build

The homepage is successful if:

* A first-time visitor understands the problem without prior context.
* The examples make the failure feel obvious and frustrating.
* The solution feels proportionate, credible, and overdue.
* The page can be shared as *the* explanation of why the project exists.
