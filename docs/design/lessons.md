# Lessons: the running log

What we learned about getting better faster on this pipeline. Reportsthatmatter-38s.6 started it; every agent appends. It is a log, not a design: short entries, newest first inside each theme, each with the evidence (a bead or a doc) and what changed or is proposed. When a lesson becomes a check, a tool or a rule, link it here and move on; do not rewrite history, add a line.

**How to add one.** At the end of your task, after your final-report retro ("Getting better faster", agent protocol rule 12), append the entries that are worth keeping to the theme they belong to (or a new theme), in the form below, in the same PR as your work. One line per entry, never hard-wrapped. Skip what is only about your report; keep what would have helped the next agent on a different one. The integrator merges concurrent appends (it is an append-only file, so conflicts are trivial) and reads the log before each release.

`- **<lesson>** (YYYY-MM-DD, <bead or doc>, <who>) <evidence in a sentence>. <What changed, or the proposal>. [status: done in <PR> | proposed | open question]`

## Measuring

- **A reference edition that keeps note markers as words makes linking markers look like a WER regression.** (2026-10-03, izw) Columbia's held-out WER rose 0.44% → 0.65% when 179 bare markers became links; its reference reads "as if it were 29 the board", so every linked marker counts as a missing word, while boundary F1 and page-break joins rose. Strip bare marker digits from both sides before WER, or report WER with and without them. [status: proposed]
- **A page-level marker score near zero with a normal page WER is a label-format mismatch until proven otherwise.** (2026-10-03, j3fw) 9/11's page-marker P/R fell from 98% to 0.2% on the hybrid switch because Wikisource labels notes "4" and the hybrid's endnotes are `[^4-1]` (note-chapter); positions matched on 299 of 299 pages and the scorer required equal strings. Comparing the note number (not the chapter, which Wikisource gets wrong on pages 123 to 125) gave 98.5% / 99.1%. Print the first mismatching pair of any near-zero match rate before theorising. [status: done, `sameLabel` in `src/lib/score/pages.ts`]
- **A scorer's per-page worst list finds defects the sample checks do not.** (2026-10-03, 8x9n) Reading the worst pages by error count for 9/11 showed three consecutive pages of Appendix B with no text of their own and 800 of 2,296 page-level word errors: the long table's `%%page%%` stamps are stacked after its last row. Neither golden pages nor quality signals look inside a table. Bead filed. [status: open, 8x9n]
- **Record the number that describes the report, and label the other.** (2026-10-03, 79ze) For a hybrid, `scores.json` now records the PDF shadow as the report's score and the adapter-vs-reference-adapter run as `adapter` (agreement of two readers, shown with deltas but never flagged), and migrates a base file that recorded the adapter as the score without reading it as a regression. [status: done, `mergeScores` and `baselines` in `src/lib/score/headline.ts`]
- **Check page anchors with code that does not share the aligner.** (2026-10-03, ivg.2) The hybrid's page stamps come from the same alignment that fills `pages.anchored`, so that number cannot fail; locating each paragraph's opening words in raw `pdftotext` page text and reading the page off its own running head found 12 of 2,079 paragraphs on the wrong page in the PDF build (pages 49 and 51 had no number at all) and 0 of 1,652 in the hybrid. [status: proposed, `pnpm ingest anchors <id>`; `docs/design/reference-editions/tools/anchors.py`]
- **When a report moves to its clean edition, its dev-set number changes meaning.** (2026-10-03, ivg.2) `pnpm score uk-saville-inquiry` now scores the edition adapter against the reference adapter that reads the same HTML (boundary P 100%, R 76.6%: it joins a boxed extract's paragraphs into one quotation), while the PDF pipeline's score (89.4% F1 against the served text) is `--shadow`; `docs/scores.json` would record the first as the report's score and look like a 10-point regression. Record the shadow run for a hybrid report and the adapter agreement as its own line. [status: proposed, bead filed]
- **Two independent readers of one HTML are a cheap test of an adapter.** (2026-10-03, ivg.2) The scorer's Python reference adapter and the report's TypeScript adapter agree on 1,322 of 1,322 paragraphs, 866 quotations, 1,439 of 1,442 markers and 0.06% of words; the disagreements were all design choices (one quotation per box, contents entries). Keep `reference.py` as the second reader and read its confusion matrix before trusting an adapter.
- **A number beats an anecdote, but only a number on the decision you changed.** (2026-10-02, 38s.10) The layout-gated page-break pass was judged by page-break join accuracy on adjudicated breaks, not by F1 over all boundaries (which moves by tenths because page breaks are 3% of line breaks). Report the metric of the decision, and the all-rows metric beside it. [status: `pnpm score` prints both and `docs/scores.json` records them]
- **Record the headline numbers where a diff can see them.** (2026-10-02, 38s.6 merger retro) Two integrators could not check a PR's join-accuracy claim because the numbers lived in PR prose. [status: done, `docs/scores.json` with previous value and delta; `pnpm scorecard` diffs it against main]
- **Gate scoring on the reference's own error rate.** (2026-10-02, 38s.12) Hillsborough's tag reference was wrong at 7.1% of page breaks and Chilcot's at 18.2% (40% wrong or missing); a score against a noisy reference measures the reference. Adjudicate 30 page breaks per reference before trusting it; fixing the reference (hybrid HTML plus tags) took Hillsborough to 0.0% and Chilcot to 4.5%. [status: `pnpm score` warns when error plus no-answer share exceeds 5% + 10%]
- **Labels need a confidence, and some rows must be dropped.** (2026-10-02, 38s.12) A reference that splits in lower case after an unfinished sentence is almost always a page-run artefact (a caption between paragraph halves); the label-flag filter caught 5 of the 6 wrong labels of the old references. Train and score on `high` and `adjudicated` rows, or report both.
- **Say how the sample was chosen.** (2026-10-02, 38s.4 golden pages, quality-harness.md) Golden pages are chosen from the hard cases, so they over-represent defects and say nothing about the rate across a report; the adjudicated random stratum is the unbiased sample. Never quote a golden-page pass rate as a defect rate.
- **A shared blind spot between producer and checker hides defects.** (2026-09-28, b78.1 "missing id") `corpus check` fingerprints the ids that the same functions produce, so 185 non-ASCII ids absent from the paragraph index passed every gate until an agent writing an introduction tripped on one. The checker must read the shipped artifact with independent code.
- **Alignment must be global and monotonic.** (2026-10-02, 38s.1) A first-anchor aligner mis-anchored a repeated-boilerplate paragraph at 27%; unique 7-gram anchors plus a longest increasing subsequence fixed it.
- **Oracle signals need a precision before they get a budget.** (2026-10-02, b78.5) `paragraphs-merged` is 10% precise because it counts every quotation paragraph and list item as a missed split; `markers-unlinked` is 59% until three oracle gaps are fixed. A ratchet on a noisy signal ratchets noise.

- **A text-matching contract must be written against the text's typography, not its bytes.** (2026-10-03, qgf7) `anchor.js` matched by exact characters, so swapping a report's source (PDF text layer to clean HTML) turned straight quotes into curly ones and would have silently orphaned every `?h=` link and saved mark with an apostrophe, though paragraph ids were unchanged. Anchors now fold quotes, dashes, ellipses, nbsp, ligatures and soft hyphens on both sides and map offsets back to the printed text. [status: done in the qgf7 PR]
- **Check stored user data against the new text before a source swap, not after.** (2026-10-03, qgf7) A read-only D1 query plus a locate() simulation over the PR's rendered text showed 1 of 12 Saville marks (the O'Donnell sentence) would have failed to anchor; nothing in `verify` or `corpus check` replays stored marks against a candidate text. [status: proposed, a `pnpm marks check <report>` that replays D1 marks (read-only) against the prerendered text, wired into the release checklist]

## Dev and held-out discipline

- **Develop on the development set, read the held-out set once.** (2026-10-02, 38s.8) The page-break rules were written from reading development errors and scored once on held-out reports from other publishers; the gain held (80.8% to 88.9%) but the held-out reports were also read afterwards to explain numbers, which is the first step to tuning on them. [status: `reports/score-sets.yaml` lists the sets; `pnpm score` reports them separately and warns when a held-out score falls; the release checklist asks whether a pass was tuned on held-out]
- **A learned model that does not transfer is information.** (2026-10-02, 38s.8) A block-type tree trained across reports scored 64-74% leave-one-report-out against the pipeline's 87-98%, because each publisher marks a quotation differently; the right form was per-report typography declared in `ingest.ts`, not a shared model. Ship rules, use trees to propose them.
- **A reference artefact looks like a regression.** (2026-10-02, 38s.9) `quoteListRunOns` took Saville's join accuracy from 92.2% to 89.7% because the reference splits boxed extracts at the PDF's page breaks; the eleven correct joins scored as missed splits. Read the diff against the page before reverting a pass, and say so in the PR.

## Tools that would have saved time

- **`pnpm ingest page --fixture` writes one page's XML without the fontspecs defined on earlier pages.** (2026-10-03, b89) A multi-page test fixture built from two such files parsed every font as empty and read no raised digits; copying the fontspecs in from the cached document XML fixed it. Make `--fixture` include every fontspec the page uses. [status: proposed]
- **Make derived data explicit.** (2026-10-03, i8en) Paragraph ids, per-block source and the page-label scheme exist only inside a function or in memory, so answering "which edition did this paragraph come from" or "what is this id" means re-running the pipeline. A generated per-block ledger (`blocks.jsonl`) beside `full.md` would let checks and outsiders read them directly. [status: proposed, decision 0002]
- **`pnpm ingest run` should print the edition report.** (2026-10-03, ivg.2) Aligned words, out-of-vocabulary words, pages anchored by their own words, repairs and disagreements are in `IngestResult.edition` but the CLI prints none of it, so each hybrid report needs a throwaway script to see its own fidelity. [status: proposed, with `pnpm ingest anchors <id>`]
- **Run `pnpm aliases generate` once, against the final text.** (2026-10-03, ivg.2) It adds every id of the new text to `published-ids.txt`; run against an intermediate re-ingest it recorded eight ids that were never published and `pnpm aliases check` failed on them. Restore both files from `origin/main` and generate again. [status: proposed, generate should record only ids of the text it is told is final, or take `--dry-run`]
- **Hybrid work needs the report, the site and the ingest linked, and the names have to agree.** (2026-10-03, ivg.2) Three worktrees, a link override in two `node_modules`, a manifest `dir` edit and an `RTM_REPORT_DIRS` directory keyed by the repo's basename (so a renamed worktree is silently not read). [status: bead 1w3, `pnpm ingest try`]
- **Concurrent sessions overwrite each other's caches.** (2026-10-02, b78.9 retro, bead 14su) `pnpm ingest verify` writes `.cache/oracle.json` in the shared report repo. Key caches by worktree and ingest version. [status: proposed]
- **Testing an unreleased ingest takes too many manual steps.** (2026-10-02, 38s.9 retro, bead 1w3) A site-only link fails with "does not provide an export" because report repos import `@rtm/ingest` from their own node_modules. Built `pnpm ingest try <branch|path> [ids]` (per-trial report worktrees, join/move list, quality and score deltas, restores links) and `pnpm score --diff <outA> <outB>`. [status: PR open, bead 1w3]
- **Learn the publish quota before uploading, not from a failed publish.** (2026-10-02, h6b, v0.18.0 integrator) D1's daily row-write limit blocked eight reports for a day and the only probe was a failed full publish. [status: proposed, `pnpm publish-report --preflight`]
- **Build the inspection kit with the check.** (2026-10-02, b78.5 retro) `pnpm ingest page <id> <vol> <pdfPage>` (layout lines beside the blocks made) and `--fixture` turned golden pages from a week of work into a day. Every new check ships with the command that shows a human what it saw.
- **A page needs its full checked text, not just its structure.** (2026-10-03, zphc retro, 7d4y) Wikisource's proofread pages give page-level word and marker references for 9/11 and the Chilcot executive summary (WER 0.79% and 0.60%); golden pages should carry checked text so every report, scans included, gets a word score. [status: 7d4y, site PR #236; `golden.yaml` text key not done]
- **Peer noise fails the gate.** (2026-10-02, b78.2) `verify.sh`'s aggregate step pulls a peer's dirty report repo and trips editorial, corpus and quality checks for reports you do not own. Check `git -C ../<repo> status` first; do not edit what you do not own.
- **Run the sourcing checklist's mechanical half by command.** (2026-10-03, ifb5 retro, design §9) Walking Duelfer II-III through stage 1 by hand, `pdfinfo -box`, `pdftotext -bbox` and a Wayback CDX listing found three facts that would otherwise have surfaced as stage 4 defects or wrong decisions, in minutes. [status: proposed, `pnpm source probe` ifb5.10]
- **A hand-kept status list drifts; derive it.** (2026-10-03, ifb5) Seeding `reports/pipeline.yaml` from artefacts found Chilcot and Lehman with no posting-queue items at all, which no list or check had shown. [status: proposed, `pnpm pipeline status` ifb5.9; ifb5.14 filed]
- **Test-time scripts that regenerate a report must not touch the shared checkouts.** (2026-10-03, pagebreak-residuals) `pnpm ingest run` and `ingest aggregate` write `full.md` into the sibling report repo, tracked in most of them; a quick loop over reports dirtied six shared checkouts until `RTM_REPORT_DIRS` pointed at worktrees. Proposal: `ingest run` refuses to write into a shared checkout (a repo on main with no `RTM_REPORT_DIRS`) unless `--shared` is passed. [status: proposed]
- **`pnpm ingest page` plus `--draft` made each case measurable in minutes.** (2026-10-03, 2hn, ky1o, j6qm) The layout lines beside the blocks showed the cause of all three defects directly (a hanging-indent inset, a lone degree-sign line, an off-face block). Keep it as the first step for any page-level bead.

## What the checks missed

- **A check that counts notes says nothing about whether a marker opens the right note.** (2026-10-03, b89/izw/kgz8) The oracle and quality signals count linked and bare markers; none asks whether `[^5-3]` opens chapter 3's note 5. What did: per chapter, the sequence of linked note numbers in reading order should be 1..n, each once, increasing (Deepwater: 10 of 10 chapters exact, one note missing). Propose a quality signal `note-sequence-per-label-group` over `[^N-C]` references. [status: proposed]
- **Two-column notes pages defeat every text-layer reader; the layout reads them cleanly.** (2026-10-03, izw) pdftotext puts Columbia's two note columns on one line each, so no regex over its output can parse them; pdftohtml's lines (left, top, raised digits, size) give 310 notes with no gaps in one pass. The same layout found Deepwater's half of note numbers set small on their own line (9pt "19" above its 11pt text). When notes are wrong, look at `pnpm ingest page` before writing another text heuristic. [status: done in ingest#56 `layoutEndnotes`]
- **Golden pages written before a fix can encode the defect's shape.** (2026-10-03, b89) Deepwater p.323's entry listed the notes appendix's "Chapter One" subhead as a body heading, and p.71's markers assertion cannot hold a paragraph that runs on to the next page under a caption. Editing a golden entry needs the reason in the entry; qzix filed for the checker. [status: open, qzix]
- **The same markdown collision keeps coming back, one report at a time.** (2026-10-03, i8en, woke) Numbered paragraphs written `N. text` become an `<ol>` with no ids: Deepwater (9ek), Chilcot (4qw), and now 384 in Hillsborough, each fixed locally. A pipeline default that escapes printed numbers, plus a signal for top-level ordered lists of prose, would close the class. [status: proposed]
- **A format can lose information silently.** (2026-10-03, i8en) `%%page N%%` can only sit between blocks, so a page that begins mid-paragraph is marked after it: 170 of 9/11's 362 proofread pages begin mid-sentence. No check measures where an anchor sits, only that it exists. When designing a format, list what it cannot express and measure how often that happens. [status: proposed in docs/design/2026-10-03-annotation-format.md]
- **Curved against straight quotation marks break every quote-bearing link and highlight.** (2026-10-03, ivg.2) The PDF text layer had 1,964 straight double and 936 straight single quotation marks; the Inquiry's HTML, like the printed report, has 976 and 804 curved ones. Ids do not change, but `anchor.js` matches a `?h=` text fragment or a saved mark exactly after collapsing whitespace, so any shared highlight with an apostrophe or quotation mark in it stops anchoring, and two editorial quotes failed. No check compares the character set of the old and new text. [status: proposed, fold quotation marks in `normalise`, bead filed]
- **A clean source repeats the source's own defects as structure.** (2026-10-03, ivg.2) The HTML splits a boxed quotation into one table per PDF page (15 quotations ended mid-sentence), numbers a note "2" that is the third, drops 10 note markers, leaves 40 as bare digits and spaces 300 closing quotation marks. `severed-into-quote` found the first; nothing found the rest but reading the markers against the notes. Pair every note with its marker and list what was assumed.
- **Page-number detection had silent gaps in the shadow.** (2026-10-03, ivg.2) The PDF reading never marked 7 of Saville's body pages and 4 of 9/11's (pages with only a header, or a header it did not read), so their paragraphs cited the page before. `printed-page-reversal` cannot see a missing number; a marker per PDF page whose neighbours agree on the sequence can.
- **Quality signals read the PDF's shapes, not the served text's.** (2026-10-03, ivg.2) `furniture-paragraph` counts a glossary's repeated "See *Baton gun*." as furniture (4 findings in the first hybrid build, 0 once glossary terms are run-in heads) and `quote-share-parity` measures content, not a margin, once quote status comes from markup (budget 2, count 1 after the extracts became one quotation each). Say which signals apply to a hybrid report. [status: open question]
- **Zero of about fifty defects were found by a check.** (2026-10-02, b78 catalogue) Readers and agents reading output found them all; checks measured word counts, baseline moves and rates set at the catastrophe. Measure placement and order, and budget per report. [status: `pnpm quality` with ratcheting budgets]
- **A heading fused into body text is the inverse of the usual heading error.** (2026-10-02, ixe) 75 of 88 Chilcot executive-summary headings are plain title case, so no heading candidate was ever proposed and "document has headings" (> 0) passed on 14. The contents page is the structural ground truth: count how many contents entries became headings.
- **Check the shipped page's shape, not its words.** (2026-09-28, deepwater; 9ek) A book gutter turned 816 paragraphs into blockquotes; paragraphs opening "N. " rendered as an `<ol>` with no id, 4,088 uncitable findings, every gate green. Quote share by page parity and top-level `<ol>` outside a blockquote are the checks.
- **Retention at 96.7% hides 270 deleted lines.** (2026-09-28, 9ek) Furniture detection masked digits and deleted record citations that recur at page edges. A retention gate set at the catastrophe cannot see a localised loss; diff the lines removed.
- **A heuristic needs guards found by reading output.** (2026-10-02, 38s.10) `layoutPageJoins` needed four guards that only reading joined paragraphs found: a footnote marker after a stop still ends the sentence; "7.44" is a label (37 of Saville's first joins were numbered paragraphs); same face except on scans; no join after a short last line. Read a sample of every new pass's output on every report before the PR.
- **Reading a scored list beats reading the report.** (2026-10-02, 38s.2) The first scorer prototype found 195 spurious paragraph starts in 9/11 where the severed-paragraph signal found 4, and the "Tue sday, Se ptembe r 11" garble nobody had seen. A reference edition finds defect classes nobody catalogued.
- **A join that moves text across a page breaks corrections scoped to the old page.** (2026-10-03, 2hn/j6qm, pagebreak-residuals) Joining a continuation into the paragraph begun on the page before made Challenger's corrections c-0034 and c-0035 (`where: {printed: 195}`) match 0 times; only a re-ingest with the new pass showed it. A pass that changes which block text belongs to should run the corrections check on every report that declares it before the PR. [status: proposed, `pnpm ingest check` already fails loudly; the report PRs carry the fix]
- **A golden page can be wrong, and the reference edition can say so.** (2026-10-03, ky1o) Philip Morris golden p.35 recorded a one-sentence paragraph as continuing the one before, but the page image (first-line indent after a short last line) and the reference edition both have it separate; the 'known pipeline defect' was the golden's. Before filing an xfail bead on a join, look at the reference edition's block for it. [status: done, golden corrected]

- **A check that borrows the renderer's pairing cannot see the renderer's pairing fail.** (2026-10-03, y0w9) `note-marker-wrong-note` took the same alignment as the renderer, so 20 of Litvinenko's sidenotes, 17 of 19 of Philip Morris's and 132 of Leveson's opened another page's note with every check green. Compare against an independent truth, here the page the PDF printed the note on. [status: `note-off-page` in `pnpm ingest verify`, budgeted]
- **Linking more markers exposes the next renderer assumption.** (2026-10-03, y0w9) Once Philip Morris's heading markers were linked, the section's title swallowed its note ("...Cigarette1919 The Court is distinguishing... -656-") in the contents and page head; unlinked digits had hidden it. Look at the rendered titles after any pass that adds links. [status: `splitSections` titles strip sidenotes; ingest PR]
- **Section membership is not checked.** (2026-10-03, n9em, 0z1o writer) Following a live alias redirect for the post showed 9/11 chapter 1's opening paragraphs served on the "preface" page: text between a `##` chapter heading and its first `###` falls into the previous section. No check asserts that a paragraph sits under the heading that precedes it in full.md. Proposal: a verify check that each section page's first heading is the heading its first paragraph follows. [status: proposed]

## Release and process

- **Make the shared-checkout rule a refusal, not a convention.** (2026-10-03, m7ga, Sonnet) Three times in one session an agent's `ingest run` loop dirtied sibling report repos and broke peers' verify, though the protocol and AGENTS.md already said "use worktrees". `run`, `baseline` and `aggregate` now refuse the shared checkout (default path and a main working tree) unless `RTM_REPORT_DIRS` points at worktrees (`pnpm ingest worktrees`) or the integrator passes `--shared`. [status: done in the m7ga PR]
- **A correction can only be proven against a re-ingest.** (2026-10-03, m7ga, from the pbj2 retro) Challenger c-0034/35 matched 0 times only after a pass change moved their text; nothing ran before the PR. `pnpm ingest recheck --passes ...` re-ingests every report declaring a changed pass and fails on that. It stops at the first stale correction per report, because `applyCorrections` throws on the first. [status: done in the m7ga PR; proposed: report every stale correction at once]
- **Two hand-read answer keys must be cross-checked.** (2026-10-03, m7ga) Golden pages and `reference/adjudicated.yaml` are both read off the PDF, and verify checks the pipeline against each but never one against the other. `pnpm ingest crosscheck` finds golden openings that contradict a join/split verdict; it found none today across six reports. [status: done in the m7ga PR]
- **Every release carries one scorecard.** (2026-10-03, 38s.6) Quality counts, oracle counts, golden pages and headline score deltas, in one block, with a checklist. [status: `pnpm scorecard`, wired into `AGENTS.md` and `scripts/ingest/README.md`]
- **Tag after squash-merge, not before.** (2026-10, memory) A tag cut on a PR branch is unreachable from main once the PR squash-merges.
- **Do not deploy before publishing when ids change.** (2026-10-02, 38s.10) Editorial ids moved in v0.18.0; the deploy had to wait for the publish, and the publish waited on a D1 quota.
- **One fix attempt per hard report.** (2026-10, memory) If a new defect class appears, stop, bead it, hold its PRs and move on; the parked report is not a failure of the loop.
- **Source choice is a bigger lever than pass tuning for structure.** (2026-10-03, zphc) 12 of 14 source PDFs are born-digital so their words are exact; what we lack is structure, and per-report source stacks (HTML, EPUB, tags, a verified vision pass for scans, anchors from the PDF) beat more heuristics on a bad extraction.
- **An inherited fix must be re-measured on the next volume.** (2026-10-03, ifb5, d0h) d0h assumed Volume I's banner fix (a `crop` of the bleed margin, 1l4) carries to Volumes II-III; their banner is inside a 612-point page with no bleed, so the same defect needs a different crop width or a rotated-text filter. Check the evidence, not the family resemblance, at stage 1. [status: in the report-source skill]
- **A recorded caveat is a claim to re-check.** (2026-10-03, ifb5, 38s.1) "The HTML omits the annexes" was a fetch gap: the CIA edition has every annex as its own page. Caveats in reference manifests should say what was fetched, not what exists. [status: reference-editions.md §3.5 corrected]
- **Read the edition's own note on the printing before choosing a clean source.** (2026-10-03, ifb5, d0h, ivg.4) Duelfer's govinfo PDFs are a revised 2005 printing (respelled names, deletions), while the CIA HTML is the 2004 text it revised; the printing says so on page 1. A clean edition can be the right structure and the wrong words. [status: report-source skill step 3; ivg.4 noted]

## Writing and publishing

- **Make "safe to keep in the repo" a tested property, not a convention.** (2026-10-03, jedz) Drafts are the point of the blog: a draft that leaks into the index, feed, sitemap or a changelog link is a publication. Tests assert each surface with only drafts present, and a changelog link to an unpublished post renders as plain text, so publishing needs no second edit. [status: done in the blog PR]
- **A generated module the Worker needs must have a freshness test.** (2026-10-03, jedz) The Worker cannot read `content/posts/` at run time, so posts ship as `src/generated/posts-bundle.ts`; a test regenerates it in memory and compares, so a forgotten `pnpm blog` fails CI instead of a post missing from production. [status: done in the blog PR]
- **Do not mark review points inside rendered prose.** (2026-10-03, jedz) An HTML comment in a post's markdown is escaped into visible text by our markdown renderer, so a flagged sentence was nearly previewed to readers with the note inline. Flags go in frontmatter `review:`, which only the draft preview shows. [status: done in the blog PR]
- **Names collide quietly.** (2026-10-03, jedz) `posts` already meant the Bluesky queue (`pnpm posts`, `src/lib/posts.ts`); the blog is `blog` everywhere in code and `content/posts/` only on disk. Grep a noun before using it for a module. [status: done]

## Pipeline record

- **A hand-kept stage record is wrong on the day it is seeded; derive it and waive known gaps by Bead.** (2026-10-03, ifb5.9, pipeline-status agent) The first run of `pnpm pipeline status` found 17 over-claims in a file seeded hours earlier: nine live reports lack PROCESSING.md, five have a missing or partial `datapackage.json`, Saville was already announced in the changelog, Chilcot and Lehman had gained `card: true` highlights, and Duelfer Volume I has no manifest entry. A row now carries `waive: {stage.item: bead}` for a gap a Bead owns, and the check says when a waiver goes stale. [status: done in the ifb5.9 PR]
- **Gate wording that no artefact can answer gets quietly relaxed.** (2026-10-03, ifb5.9) Stage 2 says the README has Scope and Materials and `datapackage.json` has a licence per file; no existing README or datapackage does, so the check accepts a Source, Scope or Materials heading and does not test licences. - **A check that must run in CI and on a laptop needs a third answer.** (2026-10-03, ifb5.9) Items that need a sibling repo checkout or the network are `unknown`, never `unmet`, so verify.sh in a clone without siblings stays quiet and `--network` fills the rest. ### Retro (Getting better faster)

- **What slowed me down:** 30 report PRs each carrying derived output (resolving them one by one was never going to work); two ingest-side defects found only by the re-ingest (Litvinenko's quote-trailing markers, the section-slug aliases); a verify run of several minutes that cannot be resumed.
- **What would have caught it earlier:** a `pnpm ingest try` run over all reports against the merged ingest main before releasing (it reports ids and sections that move, but not slug moves made by the ingest itself); a section-slug diff in `corpus check` (old slugs not in the new set and not aliased); an editorial check inside `aliases generate`.
- **One proposal:** make `aliases generate --old-ref` render the old text with the ingest version pinned at that ref, and fail `aliases check` when a published section slug has no alias or live page. That closes the 404 class for slug moves from any future pass.
